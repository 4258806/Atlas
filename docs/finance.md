# 本币金额与单一币种汇总

每台节点的原价、月均费用、剩余价值均使用节点原生币种；修改汇总币种不会修改节点价格、周期、到期时间或币种。详情、账单逐节点明细、成本对比与快照导出都不查询汇率。成本仅在相同币种内比较；导出中的多币种总额按本币分别保存，不混加。

## 顶栏配置

首页「剩余价值 → 价值与费用明细」的「显示币种」是单选项，支持 CNY、USD、HKD、EUR、GBP、JPY、RUB、CHF、INR、VND、THB、CAD、SGD。顶栏只显示当前选择的一个币种，没有附加币种复选框或并列金额。选择沿用原有浏览器配置 `fin_currency`；不是改写所有节点币种。

只在首页全部节点汇总中换算。明细弹窗的汇总数值由同一顶栏计算提供；逐节点行及单节点按量估算保持本币。未显示金额汇总时不加载汇率，离开缓存首页时暂停其刷新。

## 来源、缓存与失败处理

- 首选 [ExchangeRate-API Open Access](https://www.exchangerate-api.com/docs/free)，备用 [Frankfurter](https://frankfurter.dev/)。无需账户、密钥或付费订阅；不采集 Google 搜索或 Google Finance。
- 首选源检查成功状态、CNY 基准、数值、报价及下次更新时间；最多缓存 24 小时，来源声明的下次更新时间更早时以它为准。备用源检查基准和真实日期，至下个 UTC 日边界失效，周末等可能显示最近营业日的报价。
- 页面打开、币种需求变化、回到可见状态时检查缓存；持续打开的首页每 60 秒只检查有效期，缓存有效时不请求 API。没有后端定时任务，也不修改 Agent 上报频率。断网失败限制 15 分钟后再试，避免不断重试。
- 校验只要求当前节点及所选汇总币种需要的报价。旧备用源缺 RUB/VND 时不能填入猜测值，也不因无关币种缺失而拒绝 USD/CNY 等有效换算。
- 页面标明报价来源与来源时间。旧缓存只标为历史缓存；没有可用报价显示「汇率不可用」，不以硬编码参考数冒充当前汇率。旧 v1 浏览器缓存只可作过期回退，必须重新验证才算新缓存。
- 手动汇率仍仅保存在当前浏览器，并明确显示「含手动覆盖」；恢复来源报价会清除这些手动值。手动值不是 API 的实时数据。

报价是日常费用估算参考，不是银行成交汇率；不能承诺日更新来源具有实时市场精度。

## 署名与数据使用边界

遵循后续 UI 保持约束，已撤回顶栏新增署名行和额外币种标识；来源与状态沿用已有金额提示和汇率设置文本位置，提供方文档链接保留在本说明中。应用直接读取这两个公开源并在客户端缓存；不新增原始汇率转售、批量导出或再分发 API。源码 MIT 许可不替代数据提供方的条款。正式发行前仍需根据最终服务端方案核对数据来源的署名与使用要求，历史的新增署名行验收不代表当前 UI。

## 验证

单元与浏览器 fixture 使用明确的虚构报价，覆盖币种隔离、单选持久化、备用源缺币种、缓存过期、非法日期/基准/数值和断网回退。

`node scripts/feasibility/verify-live-fx.mjs` 只获取一次真实来源并输出来源、报价时间、有效期及币种覆盖，不输出或分发原始报价。真实 Komari 1.6.1 隔离测试：

```text
node tests/integration/reset-native.mjs BACKEND_BINARY PYTHON_BINARY BASELINE_ZIP CANDIDATE_ZIP --finance
```

它使用虚构的节点价格、真实官方后端与实际主题 ZIP，检查桌面/手机、本币隔离、单币种汇总、刷新、升级和回滚；测试浏览器需要获准联网，沙箱拒绝外连不能作为 API 或产品故障。正式发布及生产部署仍是后续独立步骤。
